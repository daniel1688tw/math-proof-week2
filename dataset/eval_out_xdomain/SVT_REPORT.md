# 自我驗證教學驗收報告（2026-07-12，分支 self-verified-teaching）

> 設計：`self_verified_teaching_design.md`。三個新能力：
> ①自動備課（先自己證對才教）②同學模式（證不對就誠實降級）③逐步教學（提示梯用盡仍卡住）。

## 一、備課管線盲測（`test_auto_reference.py`，10 題已知手寫解、盲跑不給解）

| 指標 | 結果 |
|---|---|
| verified 率 | **9/10**（唯一 unverified = M4 Darboux，歷來最難題） |
| verified 正確率（人工逐題核對） | **9/9 = 100%**——零「錯誤卻通過驗證」 |
| 單題耗時 | 288–942s（GPU 空閒給 Ollama 時） |

- 全部 9 份自動證明逐步核對無數學錯誤；M5 用了與手寫解不同路線的對稱換元證法（正確且更簡潔）。
- H5 值得一提：微調模型引導時曾把均值定理區間寫錯（$e^x-e^1$），管線自己證是對的 $[0,x]$——
  「先自己證對」的價值直接可見。
- **M4 誠實拒絕背書**正是設計目標：v3/base 兩路線都曾在這題洩漏失手，管線知道自己不會。
- 瑕疵（品質非安全）：M2/M5 教學步驟切分退到保底（整段＋通用問句）、X4 確認問句品質差。

## 二、端對端（`eval_svt_e2e.py`，真實部署鏈路）

**A. 逐步教學（A6，提示梯 2 條耗盡）**：等級 1→2（ladder0）→2（ladder1）→再連卡兩次
→ **準時自動進入 walkthrough**；逐步教出關鍵下界、學生答得出才前進、教完 4 步乾淨轉回
「請自己寫完整證明」。發現並已修復：`_STUCK_RE` 缺「不懂」，「聽不懂這步」未觸發同步重講
（加入 `不太?懂`，單元測試補案例）。

**B. 同學模式（unverified 不動點題）**：首輪確定性誠實聲明 ✓；學生質疑「你錯了吧」→
peer_reflect 觸發，回覆「對，我剛才犯了這個錯：不動點集合未必是值域」——坦白認錯並修正 ✓。
末輪對 Brouwer 的討論有些混亂（凸性講錯方向）——同學模式本就是「沒把握、請學生把關」的
降級形態，聲明已前置，屬可接受範圍，記錄之。

## 三、回歸

- 單元測試 71/71（新增 walkthrough 狀態機 7 項、peer 6 項、備課解析 6 項、stuck 缺口 1 項）。
- 標準三情境路徑不經過新分支（walkthrough 需提示梯耗盡、peer 需 unverified 標記），
  `test_driver_phase` GPU 回歸另附。

## 四、部署形態變化

```
新題目 → auto_reference.py 備課（PROVER×3 → VERIFIER → REPAIR → SEGMENTER）
   ├─ verified   → 照舊 grounded 教學（driver 全部防護與後盾生效）
   │                └─ 提示梯耗盡仍卡 → walkthrough 逐步教 → 學生自寫證明 → 審閱
   └─ unverified → 同學模式（誠實聲明、同儕探索、被質疑會反省）
```

已知限制：驗證員與證明者同一個 4B 思考模型（獨立取樣但非獨立模型），10 題樣本的
100% 精確率不保證外推到更難分布；建議新領域先抽查 verified 解再上線。
