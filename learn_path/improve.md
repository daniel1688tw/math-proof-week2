# learn_path 檢查報告與改進建議（improve.md）

> 目標回顧：做一個**微積分助教**，能「一步步引導學生思考並自己解出題目」（蘇格拉底式引導，而非直接給答案）。
> 本文評估 `learn_path/` 現有兩個子系統能否達成此目標、會遇到的問題與挑戰，並給出分優先級的改進建議。
>
> 檢查範圍：`架構設計.md`、`simple_4B_ollama copy 2.py`、`socratic_tutor/`（`common.py` / `prepare_data.py` / `train_qlora.py` / `inference.py` / `compare.py`）、訓練資料與 `trainer_state.json` loss 曲線。

---

## 一、總評：能達成到什麼程度？

| 面向 | 能否達成 | 說明 |
|------|---------|------|
| **行為/風格**（問引導問題、不直接給答案、簡短、用數學術語） | ✅ 可達成 | 基底 Qwen3-4B + 好的 system prompt 已具備大半；微調讓風格更穩定。 |
| **第一輪引導問句的品質** | ⚠️ 部分達成 | 對 10 題種子題會表現好（但那是背下來的，見問題①）；對沒見過的題目，品質取決於 4B 基底的數學能力，不穩定。 |
| **多輪、一步步引導到完整解出** | ❌ 尚未達成/未驗證 | 訓練的多輪信號全來自**小學應用題**（MathDial），微積分多輪引導**零訓練樣本、零評估**。 |
| **引導內容的數學正確性** | ❌ 無保證 | 全流程沒有任何驗證機制，4B 會給出**錯誤但語氣自信**的提示，把學生帶歪。 |

**結論**：目前的成果證明了「能讓模型表現出蘇格拉底**風格**」，但距離「能可靠地一步步把學生引導到正確的微積分證明」還有明顯落差。落差的根源不在工程（工程做得很紮實），而在**評估方法的有效性**與**內容正確性的缺位**。

## 二、做得好的地方（先肯定）

- **工程紀律優秀**：環境健檢（`_probe_env.py`）、顯存診斷（`probe_train_mem.py`）、4-bit segfault 煙霧測試、分塊續傳下載、`import pyarrow/datasets` 先於 torch 的 DLL 順序修正——6 GiB / Windows 的真實限制都被認真處理。
- **assistant-only loss masking 實作正確**：`SocraticDataset._build` 用「逐訊息遞增 prefix」累積，確保只有老師回合計入 loss，且有前綴一致性檢查與「全 -100 則丟棄」的保護。
- **訓練穩定**：`trainer_state.json` 顯示 loss 從 2.0 平順收斂到 ~0.4，`grad_norm` 健康（0.3–0.5），無 NaN。
- **文件清楚**：`架構設計.md` 把設計取捨記錄得很完整，利於後續維護。
- **雙路線務實**：Ollama（繞開 bnb/transformers segfault）+ transformers（需要 Trainer API）的分工合理。

## 三、關鍵問題（按嚴重度排序）

### 🔴 問題①：評估資料 = 訓練資料（對比結果被嚴重高估）

`prepare_data.py` 的 `_CALCULUS_SEEDS_RAW` 共 10 題，與 `compare.py` 的 `PROBLEMS` **逐字相同**；而種子在訓練集中被 `SEED_REPEAT=15` 重複。

後果：`compare.py` 拿**微調模型背過的題目**去比**基底沒看過的題目**，等於開卷考 vs 閉卷考。`d_avg`（平均分差）會大幅偏向微調模型，但**不能解讀為「會教了」，只能解讀為「背起來了」**。第一輪回覆甚至可能近乎逐字複誦種子答案。

> 這是目前最致命的方法學問題：它讓你**無法判斷微調到底有沒有用**。

**改法**：
- 把測試題目換成**不在訓練集中**的題目（另外準備 10–20 題 held-out 微積分題），種子題只用於訓練。
- 若要保留種子題做「記憶 sanity check」，請**分開報告**：種子題分數（量記憶）vs held-out 題分數（量泛化）。

---

### 🔴 問題②：評分量「形式」，不量「教學品質」

`score_socratic` 的 5 項（有問號 / 非完整證明 / 問題數 1–3 / 含數學術語 / 字數 30–300）全是**表面形式**。一個「形式漂亮但內容空泛或錯誤」的問句可以拿 5/5：

> 例：「你能想想連續性的 ε-δ 定義對這題有什麼幫助嗎？」——含術語、有問號、簡短 → 滿分，但對某些題目根本問錯方向。

**形式分高 ≠ 助教好**。這讓「優化分數」與「真正變好」脫鉤——你可能 over-fit 到評分規則本身。

**改法**（擇一或併用）：
- **LLM-as-judge**：用較強模型（或你 API 可用的 Claude）對每則引導回覆評 1–5 分的「教學有效性」：問句是否(a)在數學上正確、(b)針對這題的關鍵步驟、(c)推進一步而非空泛、(d)沒洩漏答案。提供題目 + 參考解法給 judge。
- **錨定到參考解**：先用子系統 A 產生（並驗證）的完整證明當 ground truth，judge 檢查引導問句是否指向參考解的「下一個正確步驟」。

---

### 🔴 問題③：沒有任何正確性把關（助教會自信地給錯提示）

week3 根目錄的 `baseline.py` 有 **Verify → Correct** 階段；但蘇格拉底助教**完全沒有驗證**。4B + 4-bit 的數學推理必然會出錯，而**錯誤的引導比錯誤的答案更傷**——它讓學生在錯的方向上花更多時間，且學生通常無力判斷老師錯了。

**改法（架構級，建議優先做）—— 「解答在手」的引導（solution-grounded Socratic）**：

```
題目
 │
 ├─(1) 子系統 A（Qwen3-4B-Thinking via Ollama）先產出完整證明 → 當「參考解/答案卡」
 │
 ▼
(2) 引導模型在生成每個引導問句時，把參考解放在 system/context（學生看不到）
    → 老師「知道答案」才能問出正確、指向下一步的問句
 │
 ▼
(3)（可選）對引導問句做一次輕量檢查：是否與參考解的步驟一致、是否洩漏結論
```

這直接利用了你已經做好的子系統 A，把「會解」與「會教」解耦：**內容正確性交給能驗證的求解路線，引導風格交給蘇格拉底層**。是目前投報率最高的改進。

---

### 🟠 問題④：多輪引導完全沒有訓練信號，也沒有評估

目標是「**一步步**引導到解出」，但：
- 微積分的多輪訓練樣本 = 0（種子只有「第一輪」一問一答）。
- 多輪信號全來自 MathDial 的**小學應用題**。「行為遷移」假設**多輪策略**也能遷移到微積分證明——這只是假設，未被驗證。
- `compare.py` 只測**單輪**第一個問句。整個專案沒有任何「學生回覆後，老師能否接續正確引導、糾正學生迷思、最終收尾證明」的評估。

**改法**：
- **模擬學生做多輪評估**：用一個 LLM 扮演學生（會犯典型錯誤、會回答老師的問題），與助教對話 5–8 輪，再用 judge 評整段對話是否「最終引導到正確完成」。
- 多輪 + solution-grounded（問題③）結合：老師有答案卡，模擬學生製造迷思，量「老師能否把跑偏的學生拉回」。

---

### 🟠 問題⑤：GSM8K-socratic 的格式與「一次問一個問題」目標衝突

`SYSTEM_SOCRATIC` 明確要求「**問 ONE 個問題，等學生回答**」。但 `build_gsm8k_socratic` 產生的 assistant 回合是**一整串「子問題?→計算→子問題?→計算…」的獨白**（`_clean_socratic_answer` 把 ` ** ` 換成換行，但整段仍在**單一** assistant 訊息內）。這 1200 筆（占 train ~43%）實際上在教模型「一口氣把整條拆解寫完」，**與單輪一問的目標相反**。

這也是 `prepare_data.py` 自己註解提到的 v1 回歸（「學成一次寫完整解答」）的殘留來源——降量到 1200 緩解了，但**格式本身的矛盾沒解決**。

**改法**（擇一）：
- 把每筆 GSM8K-socratic **拆成多輪**：每個「子問題? + 計算」變成一個 assistant 回合，中間插入一個假的 student 回合（如「Got it, what next?」），讓格式符合「一問一等」。
- 或進一步**降低 GSM8K 比重 / 移除**，改用 MathDial（本就是真實的一問一等多輪）為主，觀察 eval 是否更穩。

---

### 🟡 問題⑥：輕度過擬合，2 epoch 可能偏多

`eval_loss`：0.597(step100) → 0.569(200) → 0.569(300) → 0.563(400) → 0.563(484)，**約 step 200（~0.8 epoch）就停滯**；同時 train loss 仍從 0.55 一路降到 0.39。第二個 epoch 主要在背訓練資料（含種子）。

**改法**：
- 設 `load_best_model_at_end=True` + `metric_for_best_model="eval_loss"`（目前存的是**最後一步** 484，非最佳）。
- 訓練 1 epoch 或加 early stopping，省時間又少過擬合。但**注意**：在問題①修正前，eval_loss 因含種子也不完全可信，建議先修評估再調 epoch。

---

### 🟡 問題⑦：推論的 `STUDENT_NO_ATTEMPT_PREFIX` 自動補綴脆弱

模型被訓練成「微積分第一輪一定帶『I have not started yet…』」。`inference.py` 用 `_should_wrap` 的英文正則猜測要不要補綴：
- 正則只認英文關鍵字開頭（`prove|show|let|…`）；**中文輸入完全不會補綴** → 落到訓練分佈外，行為退化。
- 若學生用非典型句式提問，正則漏判，同樣脫離分佈。

這是「訓練/推論強耦合 + 脆弱啟發式」的組合，部署時容易出非預期行為。

**改法**：
- 訓練資料中**同時**包含「帶前綴」與「不帶前綴」的種子，降低對前綴的依賴，讓模型對「純題目」本身就會引導。
- 釐清**目標使用者語言**（見問題⑧），若要支援中文需在訓練資料/前綴上對應處理。

---

### 🟡 問題⑧：語言定位未明（英文助教 vs 中文學生）

`SYSTEM_SOCRATIC`、訓練資料、種子全是**英文**，助教會用英文回覆。但本專案的對話慣例是繁體中文、使用者是中文。

**需要你決定**：助教的目標使用者是英文還是中文學生？
- 若**中文**：system prompt 要求中文輸出、種子改寫成中文、評估也用中文題；否則學生體驗不佳。
- 若**英文**：現狀可，但請在文件明確標註，避免誤會。

---

### 🟢 問題⑨：文件與程式碼不一致 / 死碼（小修即可）

- **`MAX_LEN` 不一致**：`train_qlora.py` 程式預設 `512`（line 57），但同檔 docstring（line 9）寫「1024」、`README.md`（line 63）也寫 `MAX_LEN=1024`。請統一（實際生效是 512）。
- **`MemEfficientTrainer` 是死碼**：定義了分塊 CE 的自訂 Trainer，但 `main()` 實際用的是標準 `Trainer`（line 278），docstring 也說明了為何棄用（沒處理 `num_items_in_batch` → loss 被 16× 放大）。建議**刪除**或明確標 `# UNUSED`，避免誤用。
- **缺少子系統 A 當基準線**：`compare.py` 只比「微調 vs 基底（皆 transformers）」，**從未**和子系統 A 的 `--socratic` 模式（Qwen3-4B-**Thinking** + 好 prompt）比較。很可能「思考型模型 + 好 prompt」這個零訓練成本的基準就已經很強——若不比，無法證明 QLoRA 微調的必要性。

## 四、改進建議（分優先級的行動清單）

### P0 — 先做，否則無法判斷專案是否成功
1. **修評估資料洩漏**（問題①）：另備 held-out 測試題，種子題只訓練不評估；分開報告記憶分 vs 泛化分。
2. **加教學品質評分**（問題②）：LLM-as-judge，提供參考解，評正確性/相關性/推進性/不洩漏。
3. **加子系統 A 的 socratic 模式當基準線**（問題⑨）：三方對比（A-socratic / 基底-prompt / 微調），確認微調是否真的贏。

### P1 — 直接提升助教品質
4. **solution-grounded 引導**（問題③）：用子系統 A 的（驗證過的）完整證明當答案卡餵給引導層，根除「自信給錯提示」。
5. **多輪評估 + 模擬學生**（問題④）：LLM 扮學生跑 5–8 輪，judge 評整段是否引導到正確完成。
6. **修 GSM8K 格式衝突**（問題⑤）：拆成多輪一問一等，或降比重/移除。

### P2 — 訓練與部署健壯性
7. `load_best_model_at_end` + early stopping / 改 1 epoch（問題⑥）。
8. 降低對 `NO_ATTEMPT_PREFIX` 的依賴：訓練含「帶/不帶前綴」兩版（問題⑦）。
9. 釐清目標語言，必要時中文化（問題⑧）。

### P3 — 清理
10. 統一 `MAX_LEN` 文件、刪除 `MemEfficientTrainer` 死碼（問題⑨）。

## 五、建議的目標架構（整合後）

```
                         ┌──────────────────────────────┐
   學生題目 ────────────►│ 子系統 A：Qwen3-4B-Thinking   │
                         │ 產出完整證明 (+ 可選驗證)      │──► 參考解（答案卡，學生看不到）
                         └──────────────────────────────┘
                                        │
                                        ▼
   學生對話輪 ──────────► ┌──────────────────────────────┐
                          │ 蘇格拉底引導層（微調 4B 或     │
   參考解 (隱藏) ────────►│ 基底+prompt，視 P0 對比結果決定）│──► 一次一個、指向下一正確步驟的引導問句
                          └──────────────────────────────┘
                                        │
                                        ▼
                          ┌──────────────────────────────┐
                          │ 評估：held-out 題 + LLM judge  │
                          │ + 模擬學生多輪                 │
                          └──────────────────────────────┘
```

核心思想：**「會解」（可驗證的求解路線）與「會教」（蘇格拉底風格層）解耦**，並用一套**有效的**評估（不洩漏、量教學品質、量多輪）來驅動迭代。先把評估修對（P0），再決定微調是否值得保留，避免在無法判斷成效的情況下繼續調參。
