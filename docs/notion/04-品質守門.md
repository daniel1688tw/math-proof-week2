# 04 品質守門

> 規則：**任何指標低於基準 → exit 1 → 不可推送。**
> skill：`/pre-push-check`

---

## 四層守門

| 層級 | 內容 | 判定性質 |
|---|---|---|
| **Tier 0/1** | 資料集驗證、driver 單元測試、確定性指標（洩漏／拒絕／單問句／升級／教學收尾） | **零容忍**，退步即失敗 |
| **Tier 2** | 單輪評審（`judge_math_ok`／`score`／`s2_catch`／`reveal_ok`／`altmethod`，n≈13） | 容忍 ε（預設 0.05，小樣本逐項覆寫） |
| **Tier 3** | 多輪對話（評審扮學生即興對話，n=3） | **advisory**（不進 pass/fail，見下） |
| **Tier 4** | 審閱後盾找碴準確度 | 進 pass/fail |

**硬性守門 = 確定性 + 單輪評審 + altmethod（含 ε）+ 後盾。**

## 指令

```powershell
python dataset\regression_suite.py --quick     # 單元+資料集（~1 分鐘）
python dataset\regression_suite.py             # 完整（GPU + 評審 CLI，~1.5hr）
python dataset\regression_suite.py --gen-only  # 只生成存檔不評審（省額度）
python dataset\regression_suite.py --rejudge   # 讀存檔重新評審（不重跑 GPU）
python dataset\regression_suite.py --update-baseline   # 確認進步後抬高基準
python dataset\auto_gate.py --max-iters 3      # 外圈自動迭代：退件→修→重評
```

**退出碼**：`0` 通過｜`1` 退步｜**`2` 評審不完整（限額打斷）**——
生成已存檔，額度恢復後 `--rejudge` 補評即可，auto_gate 會記進度接續，
**中斷不會賠掉整輪 GPU 生成**。

## 基準管理

| 規則 | 說明 |
|---|---|
| **只升不降** | 更新基準時逐指標取高，保留較高舊地板 |
| **依評審後端分檔** | 不同裁判的尺不可互比 → `regression_baseline.json`（claude）／`regression_baseline_antigravity.json`（預設） |
| **不棘輪到幸運值** | 輸入隨機的指標（S4 學生方案、Tier 3 對話）基準要設在**可辯護的真實水準**，不是抽到過的最大值 |
| 計分卡進版控 | `dataset/regression_scores/`，含完整對話記錄，留版本歷史 |

## 評審後端

**預設**：Antigravity CLI（`agy`）+ **Gemini 3.6 Flash (Medium)**
（`JUDGE_BACKEND=antigravity`）。學生與評審皆走 Gemini，**不碰 Claude 額度**。

備援：`JUDGE_BACKEND=claude`（此時同帳號會搶額度，跑守門期間本 session 須閒置）。

### 選型結論（四檔位、各 25 次壓測皆 100% 可解析）

| 候選 | 結果 |
|---|---|
| 3.5 Flash Medium | 判準對照時對乾淨案例憑空捏造問題 → 淘汰 |
| 3.1 **Pro** | 對話層 `dialogue_math_ok_zh` 兩輪 0.333↔0.0 崩潰、把引導誤判成數學錯 → 淘汰 |
| **3.6 Flash Medium** | 判準對照 2/2、兩輪逐字一致、正確區分引導/數學、最快（6.5s）→ **採用** |

> **教訓：模型層級高 ≠ 當裁判可靠**（Pro 反而崩）。

選型腳本留存：`test_agy_stability.py`（壓測）、`test_agy_rigor.py` / `test_agy_rigor2.py`
（判準對照，一錯一對），未來換模型可快速重評。

## 為什麼對話類指標降為 advisory

四輪獨立守門實測，Tier 3（學生與評審皆模型即興生成、每輪對話路徑不同、n=3）：

- 同一批對話文字**只換一次評審**，`dialogue_math_ok_en` 從 0.0 跳到 0.3333
- `dialogue_guidance` 四輪在 0.4667↔0.8667 間全幅擺動，且每輪換不同語言掉
- **連現役 v9 模型本身都會被自己的基準判退**

處置：`ADVISORY_METRICS = ("judge_dialogue",)` —— 照算照印、不進硬性 pass/fail，
改由 Tier 4 後盾（數學正確性）＋質性審閱（引導品質）把關。

> 這是把守門從「會誤殺的儀式」修成「可辯護的判準」，比單純提高分數更重要。

## 容忍度校正紀錄

| 指標 | ε | 理由 |
|---|---|---|
| 預設 judge 指標 | 0.05 | 一般評審噪音 |
| `judge_s2_catch` | 0.08 | 僅 14 題，1 題 = 0.071 |
| `judge_reveal_ok` | 0.08 | 同型；分母隨評審漏填鍵浮動 |
| `judge_altmethod` | 0.34 | 僅 3 題 |

實測證據：**同輸入、逐字相同的輸出，評審仍會翻面**。容忍度須蓋過單題改判雜訊，
否則守門反覆誤殺。

## 限流防呆

`claude_call` 把「You've hit your limit」等限額訊息當**可重試失敗**——
