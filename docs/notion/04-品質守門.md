# 04 品質守門

> 規則：**任何硬性指標低於基準 → exit 1 → 不可推送。**
> skill：`/pre-push-check` ｜ 更新日期：2026-08-07

## 五層守門

| 層級 | 內容 | 判定性質 | GPU |
|---|---|---|---|
| **Tier 0** | 資料集驗證、`test_driver_unit.py`（250 條 / 28 組）、`test_phase_routing.py`（299 場回放） | **零容忍** | ✗ |
| **Tier 1** | 單輪確定性探針：洩漏／拒絕／單問句／提示升級／教學收尾 | **零容忍** | ✓ |
| **Tier 1b** | **多輪確定性探針**（2026-08-04 新增，`mt_*`） | **零容忍** | ✓ |
| **Tier 2** | 單輪評審（`judge_math_ok`／`score`／`s2_catch`／`reveal_ok`／`altmethod`，n≈13） | 容忍 ε | ✓ |
| **Tier 3 / 4** | 多輪對話評審（評審扮 4 種 persona 學生）、後盾找碴準確度 | **advisory** | ✓ |

**硬性守門 = Tier 0 + Tier 1 + Tier 1b + Tier 2（含 ε）。**

### Tier 1b：多輪確定性探針

補上守門最嚴重的結構性盲區：**Tier 1/2 全是單輪探針，測不到多輪行為**——
連續 6 輪守門、期間改了守衛鏈順序與 `is_stuck` 語意，104 筆回覆**始終逐字相同**。

用 8 輪固定腳本（4 題 × 中英）跑完整多輪流程，檢查 6 個確定性指標：

| 指標 | 檢查什麼 |
|---|---|
| `mt_no_leak_*` | 等級 <2 的輪次不得洩漏參考解 |
| `mt_single_question_*` | 每輪只問一個問題 |
| `mt_phase_flow_*` | 階段序列須包含 `writeup_request` → `review` → `closed` |
| `mt_ladder_conserved_*` | 提示梯只在真的送出提示時被消耗（特殊 phase 不得消耗） |
| `mt_clean_close_*` | 收尾後不得再補通用追問 |
| `mt_rectify_uninterrupted_*` | 交稿後針對缺漏的追問不得被路由進 `closed` |

**首度跑完（2026-08-06）就抓到弱點 #19**：`mt_no_leak_en = 0.25`（英文 4 題中 3 題洩漏）、
`mt_phase_flow_en = 0.75`。中文 4 題 6 項全綠。
> 注意：單輪的 `s3_refusal_en` 長期 1.0——**「單輪不洩漏」完全推不出「多輪不洩漏」**。

## 指令

```powershell
python dataset\regression_suite.py --quick     # 單元+資料集（~1 分鐘）
python dataset\regression_suite.py             # 完整（GPU + 評審 CLI，~1.5–2hr）
python dataset\regression_suite.py --gen-only  # 只生成存檔不評審（省額度）
python dataset\regression_suite.py --rejudge   # 讀存檔重新評審（不重跑 GPU）
python dataset\regression_suite.py --update-baseline   # 確認進步後抬高基準
python dataset\auto_gate.py --max-iters 3      # 外圈自動迭代：退件→修→重評
python dataset\measure_gate_noise.py           # ★ 判退時先跑：量純評審雜訊 vs ε
python dataset\measure_stuck_detection.py      # is_stuck 準確度（251 則標註）
```

**退出碼**：`0` 通過｜`1` 退步｜**`2` 評審不完整（限額打斷）**——
生成已存檔，額度恢復後 `--rejudge` 補評即可，auto_gate 會記進度接續，
**中斷不會賠掉整輪 GPU 生成**。

## ⚠️ 守門本身的已知限制（判讀結果前必讀）

### 一、9 個硬性 judge 指標中有 8 個的純評審雜訊 ≥ 自己的 ε

量法（`measure_gate_noise.py`）：取 14 輪同後端、Tier 1/2 回覆**逐字全同**的守門
（生成端零變化），差異即評審自身的不確定性。

| 指標 | 純評審雜訊 | 自己的 ε | 達標？ |
|---|---:|---:|:---:|
| `s2_catch_zh` | 0.159 | 0.08 | ✗ |
| `score_zh` | 0.135 | 0.05 | ✗ |
| `reveal_ok` | 0.115 | 0.08 | ✗ |
| `math_ok_zh` | 0.0385 | 0.05 | ✓ |
| （其餘 5 項） | — | — | ✗ |

**亦即：沒有任何真實退步時也可能判退。**

⚠️ **放寬 ε 不是解法**：`s2_catch_zh` 共 14 題，真實「多錯 2 題」= 0.143
比雜訊 0.159 還小——**任何蓋得住雜訊的 ε 都會同時放行真實退步。**

### 二、判退時的第一個動作

**逐字比對本輪與上輪的 `regression_scores/*_replies.json`。**
全同 ⇒ 生成端沒變 ⇒ 所有 `judge_*` 波動都是評審雜訊。

近四輪守門（`8be3255` / `e2c7b52` / `5426de5` …）的 Tier 1/2 回覆**每次都是 104/104 逐字相同**
——這既表示改動對固定探針零影響，也表示**分數上升不能當成修復有效的證據**。

### 三、Tier 2 多次評審取共識（效果尚未證實）

`_judge_item_consensus()`：每則探針評審 `JUDGE_SAMPLES=3` 次，布林多數決、數值中位數。
成本 38 → 114 次評審呼叫（約 +8 分鐘）。

**動機是降低變異本身，不是加大容忍。** 兩輪共識實測平均兩兩差距 0.0411 → 0.0390，
僅降 5%，n=2 完全落在雜訊內，且 `s2_catch_en`／`altmethod_zh` 反而變大。
保留它的理由是「多數決降低布林指標變異屬二項分佈性質（理論無爭議）＋成本低＋實測零壞處」，
**不是「已驗證有效」**。

> 教訓：初版比較用「單次 14 輪的極差」對「共識 2 輪的單一對差」，極差隨樣本數增大，
> 必然偏向共識、得出「7 項明顯收斂」的假成果。**比較不同樣本數時必須用平均兩兩差距。**

## 基準管理

| 規則 | 說明 |
|---|---|
| **只升不降** | 更新基準時逐指標取高，保留較高舊地板 |
| **依評審後端分檔** | 不同裁判的尺不可互比 → `regression_baseline.json`（claude）／`regression_baseline_antigravity.json`（**預設**） |
| **不棘輪到幸運值** | 輸入隨機的指標（S4 學生方案、Tier 3 對話）基準要設在**可辯護的真實水準**，不是抽到過的最大值 |
| 計分卡進版控 | `dataset/regression_scores/`，含完整對話記錄，留版本歷史 |

## 評審後端

**預設**：Antigravity CLI（`agy`）+ **Gemini 3.6 Flash (Medium)**
（`JUDGE_BACKEND=antigravity`）。學生與評審皆走 Gemini，**不碰 Claude 額度**。

備援：`JUDGE_BACKEND=claude`（此時同帳號會搶額度，跑守門期間本 session 須閒置）。

### 選型結論（四檔位、各 25 次壓測皆 100% 可解析）

| 候選 | 結果 |
|---|---|
| 3.5 Flash Medium | 判準對照時對乾淨案例憑空捏造問題 → 淘汰 |
| 3.1 **Pro** | 對話層 `dialogue_math_ok_zh` 兩輪 0.333↔0.0 崩潰、把引導誤判成數學錯 → 淘汰 |
| **3.6 Flash Medium** | 判準對照 2/2、兩輪逐字一致、正確區分引導/數學、最快（6.5s）→ **採用** |

> **教訓：模型層級高 ≠ 當裁判可靠**（Pro 反而崩）。

選型當時的一次性腳本已於 2026-08-07 清理時刪除，結論保留在此頁與
`regression_suite.py` 開頭註解。未來換評審模型時依同樣方法重測即可：
25 次連續呼叫測可解析率，再拿一錯一對的已知案例測判準是否誤殺／漏抓。

## Advisory 指標（照算照印，不進 pass/fail）

`ADVISORY_METRICS = ("judge_dialogue", "dialogue_ladder_used", "judge_backstop")`

| 指標 | 為什麼降 advisory |
|---|---|
| `judge_dialogue_math_ok_*` | 二元 × n=3；同一批文字光換評審就變動 ≥0.33、跨路徑 0.0↔1.0 全幅擺動，**連現役 v9 都會被自己的基準判退** |
| `judge_dialogue_guidance_*` | 5 分制 × n=3；四輪 0.4667↔0.8667 全幅擺動，且每輪換不同語言掉 |
| `judge_backstop` | Tier 4 拿**寫死的草稿字串**直接呼叫 `find_gaps()`（輸入固定），同一組輸入連跑三次得 **0.3333 / 0.6667 / 0.0**——涵蓋整個值域。不確定性有兩層 × n=3，一案翻面 = 0.333，無 ε 可擋 |
| `dialogue_ladder_used_*` | 學生由 LLM 即興扮演＝輸入隨機，連學生生成失敗都會讓指標歸零 |

改由誰把關：對話數學正確性 → Tier 4 後盾；引導品質 → 質性審閱；
後盾品質 → `test_backstop.py`（人工檢視）＋ `eval_backstop_e2e.py`；
多輪升級路徑 → `test_phase_routing.py` 的確定性不變式。

> 這是把守門從「會誤殺的儀式」修成「可辯護的判準」，比單純提高分數更重要。
> **只在能可靠量測的層面棘輪。**

## 兩個補上的結構性盲區

### `test_phase_routing.py`：真實對話回放（Tier 0，無 GPU）

`test_driver_unit.py` 的每句台詞都是人寫的——能證明狀態機邏輯正確，證明不了
**真模型講出來的話會不會踩中那些正則**（收尾／交稿／完成宣告偵測全在比對散文，
實測 8 種自然措辭只命中 2 種）。

把 `regression_scores/*_dialogues.json` 累積的 **299 場真實對話**（49 輪存檔、1974 輪）
回放進確定性層，檢查 5 條不變式：提示梯守恆／收尾後不補追問／`done_closed` 有可指認來源／
宣告完成後不自補問句／交稿後的長草稿不得被要求重寫。

**靈敏度已驗證**（還原修復即觸發）：還原 F3 → V3 抓到 14 筆；拿掉 `done_closed` 閘 →
V3/V4 各抓到 2 筆，證據逐字重現當年的 bug。

> ⚠️ **V4 初版是空的**——它用一個「排除帶問句回覆」的函式做判斷，該函式本身永遠不可能觸發。
> **每條不變式都必須實際還原一次 bug 驗證會響，否則只是裝飾。**

### 重度卡關型 persona（Tier 3 第 4 個）

回放 243 場既有對話量到 **`ladder_idx` 最大值 = 0**——原本三個 persona 都太會答，
`is_stuck` 在 1339 則真實學生訊息中只命中 22 則（1.6%）且從未連續兩輪，
**分級提示→逐步教學這條升級路徑在 realistic 多輪情境下從未啟動過**。

新 persona（題目 M1）措辭經 agy 實測校準至中英各 3/3 觸發 `is_stuck`——關鍵是那句
「**除非助教講出定理名稱，否則答不出來**」，少了它 LLM 學生會自己推出答案而跳出卡住狀態。

首跑即抓到弱點 #17（助教退化成重複迴圈，中英 `guidance` 皆 1 分）。
現在語料的 `ladder_idx` 最大值 = 2、等級 2 提示輪 28 次、walkthrough 42 輪。
