# 01 系統架構

> 本頁是精簡快照。**深版在 repo 的 `專案架構設計.md`**（狀態欄位表、防護鏈逐項理由、
> 取捨紀錄、擴充點）。兩者衝突時以 `專案架構設計.md` 為準。
> 更新日期：2026-08-07

## 全景

```
使用者貼上題目
      │
      ▼  ① 備課層（Ollama 思考型模型，auto_reference.py）
         PROVER×3 → VERIFIER → REPAIR → SEGMENTER → LADDER
         ├─ verified   → reference_proof + teach_steps + hint_ladder，走 grounded 教學
         └─ unverified → 同學模式（誠實聲明沒把握，不硬教）
      │
      ▼  ② 決策層（TutorDriver，純確定性 Python，1195 行）
         · stuck counter：連續卡住 0/1/2 次 → 提示等級 0/1/2（**單調遞增，不回退**）
         · 階段偵測：交草稿→review、逼問→refuse_leak、嘗試→rectify、
                     說懂了→writeup_request、證明確認完成→closed
         · 等級 2 注入提示梯內容（內建題手寫／自帶題由 LADDER 生成）
         · 提示梯用盡＋再連卡兩次 → walkthrough 逐步教學
         · review/rectify 輪 → 呼叫審閱後盾找碴，缺漏清單注入 system
      │
      ▼  ③ 生成層（Qwen3-4B-Instruct-2507 + qlora_adapter_v9，4-bit nf4，greedy）
         system 含 <REFERENCE_PROOF> + 本輪階段／等級指示
      │
      ▼  ④ 防護鏈（不合格就重生成；**每次重生成後重跑內容防護**）
         單問句截斷｜15-gram 洩漏｜on-track 防奉送｜等級 2 禁算式｜稱讚校準｜
         同儕背書｜重複偵測（含複驗）｜回問保底
      │
      ▼  回覆學生
```

## ① 備課層 `auto_reference.py`

**原則：助教必須先自己證對，才有資格教。**

| 角色 | 溫度 | 任務 | 失敗處置 |
|---|---|---|---|
| PROVER × 3 | 0.7 | 各自獨立寫一份候選參考解（繁中、LaTeX、每步交代依據） | — |
| VERIFIER | 0.2 | 獨立重新推導審查，只吐 `{"verdict","issues"}` | 該份淘汰 |
| REPAIR | 0.2 | pass 但有小瑕疵時修補一輪，再驗一次 | 再驗不過即淘汰 |
| SEGMENTER | 0.2 | 切成 3–6 個教學步驟，每步配一個確認理解小問題 | `fallback_steps()` 段落切分保底 |
| **LADDER** | 0.2 | 生成**恰 2 條**分級提示（等級 2 用） | **整份丟棄，不寫鍵** |

- 三份候選全 fail → `status=unverified` → 同學模式
- 工程細節：思考鏈需 `num_predict=8192`（3072 會被思考吃光、正文空白）；
  模型輸出的 LaTeX（`\{`、`\dots`）是非法 JSON escape，解析需**反斜線加倍重試**

### LADDER 階段（2026-08-06 新增）

**解決的問題**：管線原本不產 `hint_ladder`，手寫的 `hint_ladders.json` 只涵蓋內建 17 題
→ **使用者自帶題目一律走空梯路徑**：等級 2 退化成一句通用 meta 指示（提示深度改由 4B
模型即興拿捏，正是設計鐵律要避免的），且因梯長算 1 而**提早一輪掉進逐步教學**。

| 連續卡住 | 有梯 | 無梯（舊行為） |
|---|---|---|
| 1 | 等級 1 | 等級 1 |
| 2 | 等級 2，注入 `ladder[0]` | 等級 2，**通用保底句** |
| 3 | 等級 2，注入 `ladder[1]` | **進 walkthrough** |
| 4 | 進 walkthrough | — |

**prompt 規格由 33 條手寫提示反推**：恰兩條、依序對應證明的兩個關鍵轉折、
每條點名一個定理／構造／性質的名稱與作用、不得出現任何算式。

**五道確定性驗收**（`validate_ladder`，對 33 條手寫提示校準，實測零誤判）：
恰 2 條非空字串／每條 12–60 字／不帶新算式／不洩漏參考解／兩條 difflib 相似度 <0.85。
任一不過即整份丟棄回 `None`、**不寫 `hint_ladder` 鍵**（不是寫 `None`）——
所有失敗路徑（Ollama 離線、無法解析、驗收不過）收斂到同一結果，**最壞情況零退步**。

> 「不得帶新算式」那道是安全關鍵：等級 2 的禁算式白名單**包含當前提示文字**，
> 提示若帶算式會讓該守衛對那些算式失效。

`tutor_driver.py` **零改動**——`_ladder()` 早就會讀 `hint_ladder`，只是沒人給它。

## ② 決策層 `tutor_driver.py`

### 提示等級

| 等級 | 觸發 | 允許的內容 |
|---|---|---|
| 0 | 預設 | 只問一個聚焦問題，**禁止點名任何定理／技巧名稱** |
| 1 | 連續卡住 1 次 | 把上一問拆成更小、更具體的子問題，仍不點名 |
| 2 | 連續卡住 ≥2 次 | 可透漏提示梯對應的一條想法，**不給算式、不完成推導** |

**兩條不變式**（都曾被破壞，現已固化為測試）：

1. **等級不得回退**：曾在送出等級 2 提示後把 `stuck_count` 歸零 → 序列 `0→1→2→1→2→1`。
   對**持續卡住**的學生，支援強度在 2↔1 之間震盪（等級 1 的指示是「拆更小的子問題、
   仍不點名定理」＝給得**更少**），walkthrough 也被反覆重置拖延。
2. **提示梯守恆**：`ladder_idx` 只在 `level==2 ∧ phase is None ∧ ¬peer` 時 +1。
   `phase` 有值時 system 注入的是階段指示、根本沒有提示內容，曾照樣推進 →
   提示被消耗但學生從未看到；更糟的是 walkthrough 的進入條件就是「提示梯用盡」，
   **一串糾錯輪就能把梯吃光**。

### 對話階段（5 種 + walkthrough）

偵測優先序**由上而下、先命中先決定**：

| 序 | 階段 | 觸發 | 助教行為 |
|---|---|---|---|
| 1 | `review` | 交草稿／交稿後的長訊息（≥120 字）／帶實質內容的宣告證完（≥80 字） | 審閱找碴（走後盾），指出缺漏但不代寫 |
| 2 | `refuse_leak` | 逼問「直接給我答案」 | 一句婉拒＋一個問題還主導權 |
| 3 | `rectify` | 學生嘗試但可能有錯 | 引導他自己發現錯處 |
| 4 | `writeup_request` | 說懂了（且尚未請他交稿） | 請他寫出完整證明 |
| 5 | `closed` | `done_closed` 已 arm 且非斷言式質疑 | 收尾：不拋新問題、不提替代證法、不延伸；問一個範圍內問題就只答那一個 |
| — | `None` | 其餘 | 一般引導輪（等級指示生效） |

**收尾（`done_closed`）由四條路徑 arm**，缺一條就會出現「已完成卻還被追問下一步」：

| 路徑 | 訊號 |
|---|---|
| 審閱通過（**主訊號**） | `phase==review` 的回覆**不含問句**＝助教沒再要求修正 |
| 助教親口宣告 | `confirms_whole_proof_done()`，本輪生成後**立刻**arm（時序缺口） |
| 助教自行請學生交稿 | `asks_for_full_writeup()` 補記 `writeup_asked`，接回 review 路徑 |
| 全程無交稿步驟 | 三道閘（對話 ≥6 則、學生上一則 ≥80 字、回覆是總評式肯定）→ 補「請交稿」 |

⚠️ **學生交稿當輪不 arm**：學生說「得證」不等於證明成立。交稿當下就 arm，會讓他針對
缺漏的追問被路由進 `closed`（助教被指示「已完成、不要再問」）而**中斷糾錯**。

### 特殊模式

- **同學模式**（`is_peer()`）：`grounding=unverified` 時啟動。首輪確定性補上誠實聲明，
  想法必須標明不確定，被質疑時注入反省指示。洩漏／防奉送／禁算式／稱讚校準停用
  （無參考解可護），改由**同儕背書守衛**把關（任何「整份論證」等級的總評都會被重寫）；
  單問句與回問保底保留。
- **逐步教學**（`walkthrough`）：提示梯用盡且學生再度連卡兩次 → 自動進入。
  每輪講一步＋問一個確認問題，同一步最多重講一次；學生交草稿可隨時打斷進審閱；
  走完轉回 `writeup_request`，**學生仍要自己寫證明**。此階段允許寫式子。

### 語言處理

session 語言**逐輪跟隨學生**（≥12 個非空白字元才切，防短訊息誤判），
支援「英文題＋中文學生」與對話中途換語言。
⚠️ 備課只生繁中提示梯，`_ladder()` 的回退是「英文梯 → **中文梯**」，
故英文 session ＋ 自動備課題目會拿到混語提示（已知取捨）。

### 狀態快照

`dump_state()` / `load_state()` **整包存**（而非逐欄列舉）。舊版只存 4 個欄位，
於是 `done_closed` / `fb_idx` / `walk_*` 每輪歸零——收尾修復、保底句輪換、
逐步教學進度在逐輪 CLI 上**全部失效**。整包存之後新增狀態欄位自動跟著存。

## ③ 生成層

- 4-bit nf4 量化，本機 6GB 卡可跑；**greedy 解碼**（同輸入同輸出，使守門能做逐字比對）
- `max_new_tokens` 預設 240，教學輪 +160
- 支援 `REMOTE_GEN_SSH` 走遠端推論（大模型放伺服器 GPU；實測 WireGuard VPN 對
  port-forward 的大 payload 會斷線，ssh exec 通道穩定）

## ④ 防護鏈（順序即設計）

| # | Guard | 擋什麼 | 手段 |
|---|---|---|---|
| 1 | 單問句截斷 | 一輪問多個問題 | 截到第一個問句（教學輪除外） |
| 2 | `writeup` 階段保底 | 沒請學生寫證明 | 直接換模板 |
| 3a | 洩漏偵測 | 等級 <2 複製參考解 | 15-gram 比對（`exclude=題目敘述`）→ 重生成 |
| 3b | `spoonfeed` | 學生方向對時替他指定具體代數操作 | 重生成 |
| 3c | `formula` | 等級 2 提示夾帶新等式／不等式 | 重生成（白名單＝題目＋學生說過的話＋當前提示） |
| 3d | `overpraise` | 後盾已報缺漏卻無條件背書／訓練集 0 次的誇飾腔 | 重生成 |
| 4 | `peer_endorse` | 同學模式的權威式總評 | 重生成 |
| 5 | `repeat` | 換句話重問同一題 | difflib ≥0.85（**先剝除 driver 自己補的句尾**）→ 重生成，且**必須複驗** |
| 6 | `no_question` / `fallback` / `writeup_nudge` | 回覆沒有以問題收尾 | 重生成 → 確定性補救（三種措辭輪換／改請交稿） |
| — | `backstop` | 審閱輪漏看缺漏 | 思考型模型找碴，缺漏清單注入 system |

**最重要的不變式：每一次重生成的結果都必須再過一次內容防護（3a–3d）。**
這曾是全檔唯一未經內容檢查就送到學生面前的路徑——實測可讓一段逐字複製參考解、
結尾帶問號的回覆完整落地，正好架空招牌的抗洩漏防護。

**順序有兩處是硬要求**：`repeat` 必須早於回問保底（否則它的重生成會蓋掉剛補的問句）；
`done_closed` 的 arm 必須早於回問保底（否則「宣告完成」與「下一步該從哪裡下手」
會出現在同一則回覆）。

**重生成預算** `_MAX_REGEN_PER_TURN = 2`：教學輪每輪最多 4 次重生成曾讓守門該段
由 12 分鐘漲到 45 分鐘，學生每輪等待同步變 3–4 倍。配額用盡就走確定性補救。

## 審閱後盾 `review_backstop.py`

review/rectify 輪先讓 Ollama 思考型模型**對照參考解找碴**，把缺漏清單注入微調模型的階段指示。

- 效果：S2 糾錯 4.19 → **4.50**（跨域 4.67 → 4.92），S1/S3 逐字不變
- 找碴準確度 3/3 精準（`test_backstop.py`）；關鍵是 CRITIC_SYSTEM 要求「**教學標準**」——
  未明說的依據也算缺漏，用數學家標準會放行
- 清單為空時注入**反向指示**：「未發現缺漏。若你也同意，直接肯定學生，不要憑空發明問題」
- Ollama 不在線自動降級；`REVIEW_BACKSTOP=0` 可關閉
- 成本：每次找碴 2–4 分鐘（GPU 被 HF 佔用時後盾走 CPU）
