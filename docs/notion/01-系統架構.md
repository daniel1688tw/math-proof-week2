# 01 系統架構

## 全景

```
使用者貼上題目
      │
      ▼  ① 備課層（Ollama 思考型模型，auto_reference.py）
         PROVER×3 → VERIFIER → REPAIR → SEGMENTER
         ├─ verified   → 有可靠參考解，走 grounded 教學（全部防護生效）
         └─ unverified → 同學模式（誠實聲明沒把握，不硬教）
      │
      ▼  ② 決策層（TutorDriver，純確定性 Python）
         · stuck counter：連續卡住 0/1/2 次 → 提示等級 0/1/2
         · 階段偵測：交草稿→review、逼問→refuse_leak、說懂了→writeup_request、
                     宣告證完→closed
         · 等級 2 注入 hint_ladders.json 的預寫提示
         · 提示梯用盡＋再連卡兩次 → walkthrough 逐步教學
         · review/rectify 輪 → 呼叫審閱後盾找碴，缺漏清單注入 system
      │
      ▼  ③ 生成層（Qwen3-4B-Instruct-2507 + qlora_adapter_v9，4-bit nf4）
         system 含 <REFERENCE_PROOF> + 本輪階段／等級指示
      │
      ▼  ④ 後處理（不合格就重生成）
         單問句截斷｜15-gram 洩漏檢查｜on-track 防奉送｜等級 2 禁算式｜
         回問保底｜改寫式重問偵測
      │
      ▼  回覆學生
```

---

## ① 備課層 `auto_reference.py`

**原則：助教必須先自己證對，才有資格教。**

| 角色 | 溫度 | 任務 |
|---|---|---|
| PROVER × 3 | 0.7 | 各自獨立寫一份候選參考解（繁中、LaTeX、每步交代依據） |
| VERIFIER | 0.2 | 獨立重新推導審查，只吐 `{"verdict","issues"}` |
| REPAIR | 0.2 | pass 但有小瑕疵時修補一輪，再驗一次 |
| SEGMENTER | 0.2 | 把參考解切成 3–6 個教學步驟，每步配一個確認理解小問題 |

- 三份候選全 fail → `status=unverified` → 同學模式
- SEGMENTER 失敗 → `fallback_steps()` 確定性段落切分保底
- 工程細節：思考鏈需 `num_predict=8192`（3072 會被思考吃光、正文空白）；
  模型輸出的 LaTeX（`\{`、`\dots`）是非法 JSON escape，解析需**反斜線加倍重試**

## ② 決策層 `tutor_driver.py`

### 提示等級

| 等級 | 觸發 | 允許的內容 |
|---|---|---|
| 0 | 預設 | 只問一個聚焦問題，**禁止點名任何定理／技巧名稱** |
| 1 | 連續卡住 1 次 | 把上一問拆成更小、更具體的子問題，仍不點名 |
| 2 | 連續卡住 2 次 | 可透漏 hint ladder 對應的一條想法，**不給算式、不完成推導** |

### 對話階段（5 種）

| 階段 | 觸發 | 助教行為 |
|---|---|---|
| `review` | 學生交草稿／實質宣告證完 | 審閱找碴（走後盾），指出缺漏但不代寫 |
| `rectify` | 學生嘗試但有錯 | 引導他自己發現錯處 |
| `refuse_leak` | 學生逼問「直接給我答案」 | 一句婉拒＋一個問題還主導權 |
| `writeup_request` | 學生說懂了 | 請他寫出完整證明 |
| `closed` | 證明已確認完成 | 收尾：不拋新問題、不提替代證法、不延伸；問一個範圍內問題就只答那一個 |

### 特殊模式

- **同學模式**（`is_peer()`）：`grounding=unverified` 時啟動。首輪確定性補上誠實聲明，
  想法必須標明不確定，被質疑時注入反省指示。洩漏／防奉送／禁算式防護停用（無參考解可護），
  單問句與回問保底保留。
- **逐步教學**（`walkthrough`）：提示梯用盡且學生再度連卡兩次 → 自動進入。
  每輪講一步＋問一個確認問題，同一步最多重講一次；走完轉回 `writeup_request`，
  **學生仍要自己寫證明**。此階段允許寫式子。

### 語言處理

session 語言**逐輪跟隨學生**（≥12 個非空白字元才切，防短訊息誤判），
支援「英文題＋中文學生」與對話中途換語言。

## ③ 生成層

- 4-bit nf4 量化，本機 6GB 卡可跑
- `max_new_tokens` 預設 240，教學輪 +160
- 支援 `REMOTE_GEN_SSH` 走遠端推論（大模型放伺服器 GPU；實測 WireGuard VPN 對
  port-forward 的大 payload 會斷線，ssh exec 通道穩定）

## ④ 後處理防護（6 種 guard）

| Guard | 擋什麼 | 手段 |
|---|---|---|
| `repeat` | 換句話重問同一題 | difflib 相似度 ≥0.85（教學輪除外） |
| `spoonfeed` | 學生方向對時替他指定具體代數操作 | 重生成 |
| `formula` | 等級 2 提示夾帶新等式／不等式 | 重生成（白名單＝題目敘述＋當前提示＋學生說過的話） |
| `no_question` | 回覆沒有以問題收尾 | 重生成 |
| `fallback` | 重生成後仍缺問句 | 確定性附加追問（三種措辭輪換） |
| `backstop` | 審閱輪漏看缺漏 | 思考型模型找碴，缺漏清單注入 system |

另有：單問句截斷（多問號截到第一個）、15-gram 洩漏檢查（等級 <2 命中即重生成）。

## 審閱後盾 `review_backstop.py`

review/rectify 輪先讓 Ollama 思考型模型**對照參考解找碴**，把缺漏清單注入微調模型的階段指示。

- 效果：S2 糾錯 4.19 → **4.50**（跨域 4.67 → 4.92），S1/S3 逐字不變
- 找碴準確度 3/3 精準（`test_backstop.py`）；關鍵是 CRITIC_SYSTEM 要求「**教學標準**」——
  未明說的依據也算缺漏，用數學家標準會放行
- Ollama 不在線自動降級；`REVIEW_BACKSTOP=0` 可關閉
- 成本：每次找碴 2–4 分鐘（GPU 被 HF 佔用時後盾走 CPU）
