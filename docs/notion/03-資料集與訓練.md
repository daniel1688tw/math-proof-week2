# 03 資料集與訓練

## 資料集是什麼（重要觀念）

資料集是**訓練集，不是題庫**。

- 訓練時：50 題 × 830 例對話把「引導語氣、不給答案、拒絕逼問」烤進 adapter
- 推論時：模型**不查資料集、不做檢索**。面對新題目靠的是現場備課產出的參考解
- 唯一在推論時被讀取的資料資產是 `hint_ladders.json`（那 50 題的預寫提示），
  使用者自帶的題目沒有提示梯，等級 2 改用泛用指示「點出關鍵定理或想法名稱（不給算式）」

| 資產 | 規模 | 推論時使用 |
|---|---|---|
| `train.jsonl` / `val.jsonl` | 747 / 83（合計 830，中英平行） | ✗ |
| `problems.json` | 50 題 | 僅內建題目情境 |
| `hint_ladders.json` / `_en` | 50 題的分級提示 | ✓（內建題目） |
| 評估題（held_out / hard / xdomain） | — | ✗（只給評估腳本） |

**內容全部由人手寫並對照參考解驗證**，不是叫小模型生成的——這是資料品質的前提。

## 資料集組成

五類題型（A–E）各 10 題，共 50 題；每題配多段對話，涵蓋三種學生 persona
（confused / fragile / demanding）與五階段蘇格拉底策略。詳見 `dataset_plan.md`。

行為專項對話：

| 專項 | 檔案 | 針對 |
|---|---|---|
| 抗逼問 | `dialogues_resist.py` | 學生要求直接給答案 |
| 寫證明與審閱 | `dialogues_writeup.py` | 請學生自寫、審閱草稿 |
| 替代證法 | `dialogues_altmethod.py` | 順著學生自己的方法走 |
| 跨題型旅程 | `dialogues_journey.py` | 剛學完但易卡住的多輪對話（**尚未成功上線**） |

## 訓練

### 本機（RTX 4050 6GB）

```powershell
$env:ADAPTER_DIR = "week3\dataset\qlora_adapter_v9"   # 預設 qlora_adapter_new，不要覆蓋現役
$env:MAX_LEN = "1024"; $env:EPOCHS = "3"; $env:GRAD_ACCUM = "8"; $env:EVAL_STEPS = "20"
$env:OPTIM = "adamw_8bit"          # ★ 不要用 paged_adamw_8bit（abrupt kill 後 init error）
$env:NEFTUNE_ALPHA = "5"
conda run -n lora_project --live-stream python learn_path\socratic_tutor\train_qlora.py
```

### 伺服器（4090，bf16，Docker）

`server_train/docker-compose.v*.yml`，一輪約 13 分鐘。用前務必 `nvidia-smi`
確認即時用量再挑 GPU，不要沿用固定 GPU 編號的慣例。

### 超參演進

| 版本 | MAX_LEN | 資料量 | eval_loss | 結果 |
|---|---|---|---|---|
| v8 | 640 | 814 | — | 曾為部署版 |
| **v9（現役）** | **1024** | 814 | 1.052 | 守門 25/25 全綠，升版 |
| v10 | 1024 | 830 | 1.042 | **判退**（收尾過度延伸） |
| v11 | 1024 | 830 | 1.044 | **判退**（同上重現） |

**v9 的關鍵發現**：MAX_LEN=640 會截掉 26% 訓練樣本的**尾端**——正是對話收尾與審閱輪，
也正是「完成後仍多講」這個弱點的訓練面根因。改 1024 重訓後英文單輪指標全面提升。

**教訓**：eval_loss 更低 ≠ 行為更好。v10/v11 的 loss 都優於 v9，行為卻退化。

## Adapter 傳輸紀律（伺服器 → 本機）

- 分塊拷貝後**逐塊 SHA256 比對**
- 曾遇到 13 塊中 1 塊在 VPN 上損毀 → 逐塊比對定位、只重下壞塊，不必整批重傳
- 也曾遇到大小相符但 SHA 不符的舊檔殘留 → **絕不可只信任檔案大小**

## 本機 6GB 卡的兩個坑

1. **連跑兩輪守門之間必須 `ollama stop`** —— 後盾的 Ollama 模型駐留 3.2GB
   會使下一輪載入 4-bit 基底 segfault（撞兩次同一進度點才查出）
2. **跑守門前先關 Antigravity IDE** —— 桌面應用會啟 16 個背景進程搶 GPU，
   導致 4-bit 載入在 30–40% segfault（連撞四次才鎖定）：
   `taskkill /F /IM "Antigravity.exe"` + `"Antigravity IDE.exe"`。
   `agy` CLI 憑證存磁碟，關 IDE 不影響評審呼叫。
