## 判退存證：四個「做了但不採用」

| 實驗 | 做了什麼 | 為什麼不採用 |
|---|---|---|
| **Qwen3-8B** | 伺服器訓練 8B adapter（eval_loss 0.266，煙霧測試 OK） | 單輪品質升（altmethod 1.0/1.0），但多輪數學滑落兩輪重現（dialogue_math_ok 0.667×2）→ 守門擋下，4B 續任 |
| **BoN + 驗證器** | 生成器＋思考型驗證器共存，選擇性驗證含式子的回覆；校準後抓錯 3/4、誤殺 0/3 | **實戰 273 輪只有 1 輪真的攔到（0.4%）**——微調＋driver＋後盾已把可驗證的數學錯誤壓到極低，卻要多 8GB 顯存與延遲 |
| **v10 adapter** | 資料集 800→830（+journey/on-track/outline-refusal），eval_loss 1.042 優於 v9 | H5 案例在 **4 次獨立生成中全部**出現「學生證完後助教未經請求主動延伸」，其中一輪產生新的數學錯誤（誤稱「更弱命題」為「等價命題」）→ 真實可重現的收尾紀律退化 |
| **v11 adapter** | 同資料集重訓，假設 #11 driver 修復能兜住 v10 的問題 | 同問題重現（H5 延伸 6 輪、把學生拖進 x<0 推廣），X4 另有模型級數學錯誤（誤稱單位矩陣為反例）→ 判退，部署維持 v9 |

**重要區分**：v11 那一輪的兩件事可分離——**#11/#12 的 driver 修復（純確定性層）
乾淨通過守門並上線；v11 模型本身判退**。分支叫 `training-iter-v11`，實際部署的
是 `qlora_adapter_v9` + 新 driver。

> 830 例資料集本身經人工撰寫並對照參考解驗證，**問題不在資料有誤**，
> 而在訓練後的行為交互作用（疑似 journey 資料「連續多輪深入追問」的訓練訊號
> 讓模型收尾後更傾向順勢多教）。資料保留供下次迭代。

## 工程教訓（可跨專案複用）

| 教訓 | 來源 |
|---|---|
| **離散決策交給程式碼，模型只管語氣** | v4→v6 三次驗證 |
| **模型層級高 ≠ 當裁判可靠** | Gemini 3.1 Pro 當評審反而崩 |
| **eval_loss 更低 ≠ 行為更好** | v10/v11 loss 優於 v9 卻判退 |
| **輸入隨機的指標不可棘輪到幸運最大值** | altmethod_en 基準誤設 1.0 後必然誤判退步 |
| **同輸入逐字相同的輸出，評審仍會翻面** | 守門容忍度校正的實測依據 |
| **絕不可只信任檔案大小，一律以 SHA256 為準** | adapter 分塊傳輸損毀 |
| 思考鏈需 `num_predict=8192` | 3072 會被思考吃光、正文空白 |
| 模型輸出的 LaTeX 是非法 JSON escape | 解析需反斜線加倍重試 |
| 找碴要用「教學標準」而非「數學家標準」 | 後者會放行未明說的依據 |
| 質性內容跨多輪一致 > 分數波動 | v10 判退的判定方法 |
