## 設計岔路（人工定案）

| 岔路 | 選擇 | 理由 |
|---|---|---|
| 完成後帶問句的反思要不要跳出 `closed`？ | **Fork B：一律進 closed 簡答**，只有斷言式質疑（「你錯了」）才落回一般流程 | 已完成的證明必經 review＋後盾複核，非斷言的「你確定嗎」簡答即可 |
| 提示梯生成失敗怎麼辦？ | **整份丟棄，不寫鍵** | 所有失敗路徑（離線／解析失敗／驗收不過）收斂到同一結果 ⇒ **最壞情況零退步** |
| 要不要把 hint 移出禁算式白名單？ | **不移**，改為「讓生成的梯保證無算式」 | ADV1 的手寫提示**刻意**帶算式並依賴白名單放行，移除會打壞既有題目 |
| `judge_backstop` 要不要降 advisory？ | **降**（人工授權） | 固定輸入連跑三次得 0.0 / 0.333 / 0.667，涵蓋整個值域，無 ε 可擋 |
| 提示梯用量要不要做成硬性指標？ | **不做**，改 advisory + `test_phase_routing.py` 把關 | 學生由 LLM 即興扮演＝輸入隨機，連學生生成失敗都會讓指標歸零 |

### 弱點 #17 的診斷過程（最值得記的一則）

**我連續兩批都在修症狀，而診斷只花了一次回放。**

1. **第 1 批（症狀）**：driver 補的保底句把 difflib 相似度稀釋到門檻以下（實測 0.768 < 0.85）
   → `repeat` 根本沒觸發。修法：比對前剝除 driver 自己補的句尾。
2. **第 2 批（症狀）**：`_regen` 回傳同一段文字卻不複驗就採用。修法：重生成後複驗、
   教學輪推進 `walk_idx`。→ 逐字重複確實消失，**但 `guidance` 仍是 1 分**，
   失敗模式只是換出口（改成直接洩漏答案後宣告放棄）。
3. **第 3 批（根因）**：回放逐輪查狀態才看到等級序列是 `0→1→2→1→2→1`。
   `_tutor_turn` 在送出等級 2 提示後把 `stuck_count` 歸零——對**恢復的**學生是對的
   （但 `step()` 本來就會歸零，該行多餘），對**持續卡住**的學生有害：下一輪掉回等級 1
   （給得更少），支援強度震盪而非單調遞增。**刪掉該行即可。**

結果：等級序列 → `0→1→2→2→walkthrough`，實測對話成為單調遞增的降階梯，
中英 `guidance` 1 → 2。**殘留**：分數仍偏低，新評語指向「助教在子目標間跳躍」。

## 工程教訓（可跨專案複用）

| 教訓 | 來源 |
|---|---|
| **離散決策交給程式碼，模型只管語氣** | v4→v6 三次驗證 |
| **任何「靠模型自律」的設計都是缺陷** | 收尾偵測靠散文比對，8 種措辭只中 2 種 |
| **模型層級高 ≠ 當裁判可靠** | Gemini 3.1 Pro 當評審反而崩 |
| **eval_loss 更低 ≠ 行為更好** | v10/v11 loss 優於 v9 卻判退 |
| **輸入隨機的指標不可棘輪到幸運最大值** | altmethod_en 基準誤設 1.0 後必然誤判退步 |
| **同輸入逐字相同的輸出，評審仍會翻面** | 守門容忍度校正的實測依據 |
| **看起來全綠不等於測到東西** | `test_phase_routing.py` 的 V4 初版永遠不可能觸發 |
| **測試素材必須實測它真的觸得到那道閘** | 標榜「>60 字」的 fixture 實測只有 48 字 |
| **修症狀前先花一次回放找根因** | 弱點 #17 連修兩批症狀才找到根因 |
| **比較不同樣本數時必須用平均兩兩差距** | 用「極差」比較必然偏向樣本多的一方，得出假成果 |
| **絕不可只信任檔案大小，一律以 SHA256 為準** | adapter 分塊傳輸損毀 |
| **判斷卡死 vs 只是慢要用 CPU 時間增量** | 40 秒內 <0.5 秒＝卡死；單次 GPU 取樣會抓到空檔誤判 |
| **長時間任務不要丟進 subagent 的背景** | subagent 背景化後結束 session，進程隨之死亡 |
| 思考鏈需 `num_predict=8192` | 3072 會被思考吃光、正文空白 |
| 模型輸出的 LaTeX 是非法 JSON escape | 解析需反斜線加倍重試 |
| 找碴要用「教學標準」而非「數學家標準」 | 後者會放行未明說的依據 |
| 質性內容跨多輪一致 > 分數波動 | v10 判退的判定方法 |
